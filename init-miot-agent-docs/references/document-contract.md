# 六份协作文档的内容契约

这些是输出职责与建议栏目，按真实项目填写并与现有内容合并，不将示例值或空白栏目当成项目事实。默认中文，沿用项目已明确的语言要求。

## AGENTS.md：稳定规则

应包含：

- 适用目录、项目边界和插件级特殊约束；适用的公共规范与长期记忆/知识库入口。
- 继续任务先读取 TASKS 和 HANDOFF；首次参与或架构变化时查 PROJECT；涉及重要历史选择时定点查 DECISIONS。上下文未失效时不重复读全套。
- 修改代码前先确认 model、实际配置、SDK/API 和目标宿主，按知识库主题检索并读完整相关小节；说明本次引用的文件/章节。纯文档任务不要求预读插件实现专题。
- 保留既有业务修改，最小改动、不顺手升级、重构或格式化；不得假定参考组件在目标存在。
- 规划/实现/复核按用户授权分工，只有一个代码写入者。任务状态和执行者字段不是授权或文件锁。
- 有阶段进展、关键决定、验证、阻塞、切换或收尾时及时更新对应文档；简单问答无需机械更新。
- 验证命令、执行目录、结果及限制；实现完成、本地检查与真机验收分开记录。代码变化后重新判断证据有效性。
- 切换前结束本轮写入、记录持续进程及下一步；接手时重新核对 Git 与源码，不盲信交接。不强制每次切换提交或 stash。
- 故障时保留现场；资料缺口仅停止受影响部分，尝试定点检索后仍不能确定的重要问题才询问。
- 本机协作文件的忽略与备份限制；创建 worktree 时核对未提交/忽略的规则、任务、代码、依赖和 SDK 路径。

不将某一工具特有权限、MCP 或技能的安装情况写成两个工具天然共享。不记录密钥、设备账号、令牌或完整敏感日志。

## CLAUDE.md：共享规则入口

新文件默认内容：

```markdown
@AGENTS.md
```

已有 Claude 专用内容保留，通用规则在 AGENTS 维护；先检查现有导入链再补充。

## PROJECT.md：项目事实和架构

建议栏目：

1. 项目用途和核对日期。
2. 环境表：插件绝对路径、真实 Git 根目录、SDK 根目录、package_path、npm 包、入口与配置来源。
3. 设备和兼容性表：model、地区、通信、最低 API、本地 SDK、宿主 API/版本、固件与真机条件；未知项写待确认。
4. 目录职责：仅列源码中已确认的入口、页面、协议/Spec 映射、语言选择、资源与复用组件。
5. 调试/检查命令：注明执行目录、脚本来源、是否执行，缺失脚本如实说明。
6. 知识库位置、按需加载规则及待核对事项。

保持稳定概况，不把每次 HEAD、最新 diff 和任务进度放在这里。最低要求、本地 SDK 和实际宿主能力分开写；不从 App 展示版本号推断 API。

## DECISIONS.md：决定与原因

每个重要决定记录：

- 编号、绝对日期、状态（提案/待确认、已采纳、已替代）。
- 背景、主要选项、决定、理由、约束和适用范围。
- 用户确认、现有有效规则或既有实施授权的来源。
- 被替代时指向新的决定编号并保留旧记录。

源码只证明现有实现，不证明最初理由。不要为填满文件猜测历史；没有可确认决定时明确说明，并记录本轮用户已授权采用的协作结构。初始化前既有决定全部保留。

## TASKS.md：任务目标与状态

任务表字段：编号、名称、执行者/角色、状态。状态可采用规划中、待实施、实现中、待复核、待真机、完成、受阻。

每项任务至少有需求与授权范围、验收条件、步骤进度、验证摘要和未完成项。代码/记录的实时细节放在 HANDOFF，重要决定链接 DECISIONS，避免多份正文互相漂移。

初始化新建任务如 `AI-<日期>-<可用序号>`，先检查是否重号。验收是文档和忽略规则，不是项目整体功能完成。已有业务修改只记录为接手基线，不自动生成已完成业务任务。

## HANDOFF.md：最近现场与下一步

建议栏目：

```markdown
# 最近一次任务交接

## 任务与现场
- 任务编号、用户需求、最近执行者/角色、绝对日期时间和时区。
- 插件路径、Git 根目录、worktree（如有）、分支和 HEAD；无 Git 时如实说明。
- 本轮是否停止写入、仍运行的相关进程与归属。

## 接手前已有修改
- 原有修改清单、与本任务的关系；必要 diff/内容基线位置。

## 本轮完成
- 本次新增/合并文件、目的和当前状态；原有未完业务任务的引用。

## 验证与限制
- 实际时间、目录、命令/检查方式、结果、对应代码状态。
- 未测试项、未知配置、阻塞、忽略文件的备份/同步限制。

## 下一步
- 接手者能直接执行的动作；无新增业务任务就等待用户需求。
```

HANDOFF 保持精简，只保留最近操作及恢复必需的约束。既有交接中的有效业务信息不能被新的初始化记录掩盖；保留在原任务中并引用，必要时保留简短历史段落。详细旧输出引用已存在的记录，不把聊天全文搬进来。
