# 初始化 Agent 协作文档 · 米家 IoT 插件

为目标插件建立可供 Codex 与 Claude Code 轮流使用的项目文件。默认执行初始化，而非仅给出方案。只改协作文档和必要忽略配置，不授权业务开发、依赖安装、启动 Metro、构建、提交或推送。

## 范围与交付

采用用户选定的六文件结构，不自动改成 STATE.md 体系：

```text
<插件根目录>/
├── AGENTS.md
├── CLAUDE.md
└── docs/ai/
    ├── PROJECT.md
    ├── DECISIONS.md
    ├── TASKS.md
    └── HANDOFF.md
```

已有文件增量合并，保留有效规则、决定和未完成任务；重复调用不重复导入、重复追加忽略规则或重新宣称首次初始化。已有 STATE.md 等入口时，保留原文并明确各信息的权威位置，复用或引用其有效内容；不留下两套彼此独立更新的状态。跨体系迁移涉及无法确定的产品要求时，只询问该问题。

先读 [文档内容契约](references/document-contract.md)，按其中的职责填充真实事实，避免生成空模板或复制旧项目内容。

## 1. 定位插件与现有规则

- 优先使用用户明确给出的目标，否则检查当前工作目录。区分插件根目录、SDK 根目录和各自 Git 根目录；目录名和外层 Git 根目录均不足以证明目标。
- 用 `project.json`、入口和 `package.json` 定位米家插件。若当前是 `projects/` 集合或参考资料库且没有唯一目标，先询问目标插件；不能默认初始化参考项目、整个 SDK 或所有插件。
- 目标无独立 Git 时，核对实际归属；外层 SDK 可能忽略整个 projects。没有可用 Git 仓库时不自动 git init，也不改无关外层仓库来假装完成 Git 忽略；完成能做的文档并报告具体限制。
- 读取路径上适用的 AGENTS/CLAUDE、子目录规则和本项目已有 docs/ai；继承已有长期记忆与知识库协议。使用 `rg` 定点搜索，排除 node_modules、构建产物和分发包，避免遍历全部插件。
- 记录分支、HEAD、暂存/未暂存/未跟踪状态及本轮写入前的必要内容基线，保护已修改文档与业务文件；暂存区保持不变。
- 简短说明目标、现有修改、本轮文档范围与验收方式，然后执行已授权的初始化。

## 2. 核对米家项目事实

仅读取填写文档所需的配置、入口和少量相关源码：

- `package_path`、npm 包名与版本、入口注册、主要目录和导航方式。package_path 不是完整设备 model 的可靠证据。
- `project.json` 的 `min_sdk_api_level`；实际 SDK 的 package.json/api_level 和导出常量。分别记录来源，不互相替代。
- 实际 Host.apiLevel、宿主版本、固件、完整 model、销售地区和 iOS/Android 真机条件：无证据写“待确认”，不为填表安装或运行宿主。
- 从调用核对 Spec/Wi-Fi、BLE 或其他通信方式与属性/事件定义位置，不默认全部插件采用参考项目的协议。
- 从实际语言选择入口核对已启用语言和回退；资源文件存在不代表对应语言已启用。RTL 能力另核对目标 API 与宿主。
- 核对项目与外层 SDK 脚本、执行目录、所需依赖。仅记录有源码依据的命令，并区分“脚本存在”和“已运行成功”；无 test/build 脚本就如实记录。

不要 require/import 会改变 cwd、文件权限或启动服务的 SDK 配置来做静态探测；读取文本或 JSON 即可。

本机可参考的规范入口是 `/Users/zhuxinlei/Documents/米家iot/AGENTS.md`，知识库为其下 `knowledge-base/`；先核对路径存在及目标项目自己的配置，再写进文档。其他机器采用实际位置，不生成失效引用。本次仅改协作资料和忽略规则，无需预读插件实现知识库。为未来业务修改保留按需路由、正文小节与版本边界的核对要求。

米家 API 约束按有效项目规则记录：10012 专项不推断其他版本；国际化常规示例要求 10084+、阿拉伯语/希伯来语与 RTL 要求 10098+，仍需核对目标宿主。不能将较新的本地 SDK 视为提高了插件最低要求。避免混用涂鸦 Ray 的 API 或 DP 模型。

## 3. 生成与合并

- AGENTS 保存通用规则和本插件必要差异，不复制参考项目特有组件保护区、版本、绝对路径、命令或业务假设。
- CLAUDE 不存在时创建 `@AGENTS.md`。存在则保留原文，检查直接/间接导入和规则冲突，只补必要引用，避免循环和重复导入。
- PROJECT 按目标源码重新填写。DECISIONS 不搬运别处的决定；未知历史理由与未获确认的提案明确标记。
- TASKS 增加唯一编号的“初始化协作文档”任务；保留原业务任务及状态。HANDOFF 记录本轮初始化，保留尚有效的原约束和未完事项或明确引用原任务，不能以初始化完成宣称业务完成。
- 不复制 `com.cp1bm` 的 TASKS、DECISIONS、HANDOFF、快照或验证记录。它只提供文件职责与协作机制的参考；无需在每次调用时重读它。
- 不把当前初始化任务绑定成永久行为约束。后续日常开发仍以用户需求和目标项目规则为准。

## 4. 本机 Git 忽略

本技能默认将本次协作资料作为本机文件。在目标真实仓库 `.gitignore` 增量添加六个根目录锚定路径，已有生效规则不重复添加：

```gitignore
/AGENTS.md
/CLAUDE.md
/docs/ai/PROJECT.md
/docs/ai/DECISIONS.md
/docs/ai/TASKS.md
/docs/ai/HANDOFF.md
```

仅在实际保存必要基线时另加 `/docs/ai/.local/`；优先保留既有忽略规则，不为此将整个 docs 或无关文档隐藏。参考项目已有 `/docs/ai/` 时不必改窄或叠加重复项。

忽略不会取消已跟踪文件。遇到既有已跟踪文档，保留跟踪状态并报告限制，不执行 git rm --cached、强制添加、stash 或 reset。用户已明确共享或提交某文档时，按明确要求调整此默认策略。

这些本机文件不随远端 clone 或 worktree 自动完整迁移。HANDOFF 应注明备份/同步限制；技能安装本身不等于资料已经备份。

## 5. 验收与交付

- 检查六文件齐备、真实信息有来源、引用可解析、CLAUDE 无重复/循环入口，现有规则/任务/决定得到保留。重复调用只补缺口和刷新有证据的过时事实。
- 在目标仓库运行 `git diff --check -- <本次修改的已跟踪文件>`，另检查被忽略的新文档；用 `git check-ignore -v` 验证需要忽略的未跟踪文件，用 `git ls-files` 区分已跟踪例外。
- 对照初始基线确认原有无关业务、配置、锁文件及暂存区保持不变，不把先前 Git 脏文件都算作本次成果。新文档失败时修复文档；不顺手修业务错误。
- 更新初始化任务的实际验收结果和最近交接。分别写清已检查、未检查；未做新会话加载、构建、真机测试就不能声称通过。
- 简要返回生成/合并文件、实际插件与 Git 边界、忽略结果、验证及剩余限制，给出下一次接手入口。现有授权内的可逆文档操作不逐项请求确认。
